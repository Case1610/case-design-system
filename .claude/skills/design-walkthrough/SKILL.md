# 目的

このプロジェクトは docs/principles.md にある原則と docs/decisions.md にある判断ログを土台に、
壁打ち形式（ユーザーに具体的なトレードオフを選ばせ、そこから原則やスキルを逆算する）で進めている。
このスキルは、新しいセッションでも同じやり方・同じ文脈で再開するためのもの。

# 手順

1. 次のファイルを読み、現在地を把握する。会話の前提をユーザーに聞き直さない。
   - CLAUDE.md
   - docs/status.md（現在のフェーズと直近の状態）
   - docs/principles.md（確定した原則と、その裁定プロトコル）
   - docs/decisions.md（原則からの例外とその根拠）

2. docs/status.md の「次のアクション」を確認し、そこから会話を始める。
   「何をしましょうか」とは聞かない。状況を一言で要約し、次の具体的な論点を提示する。

3. 議論の進め方は、これまでと同じ形式を守る。
   - 抽象的な二択（「Aは重要ですか？」）ではなく、具体的なシナリオ（「〜という場面ではどうしますか」）で問う
   - AskUserQuestion で選択肢を提示し、ユーザーの直感的な判断から原則を逆算する
   - 原則同士が衝突する場合は、docs/principles.md の「原則同士が衝突したときの裁き方」
     （観察・仮説・比較・記録）に沿って裁く
   - 新しい判断が出たら、会話内に留めず、その場で docs/ 配下のファイルに書き込む

4. フェーズが完了したら docs/status.md のチェックリストと CLAUDE.md を更新する。

# 気をつけること

- 説明を長く書きすぎない。すでに docs/ にある内容を会話内で繰り返さない（ファイルを参照させればよい）
- 一度に多くの論点を出さない。1トピックずつ、具体例に絞って進める
- ユーザー自身の言葉（Tailor to the Case など）や既存の原則と矛盾する提案をしない
- 実装フェーズ（トークンの機械的な生成、コンポーネントの雛形量産など）に入ったら、
  判断が伴わない作業はサブエージェントへの委任も検討してよい。設計判断そのものは委任しない
